# Архитектура Timer 3

## Обзор

Timer 3 — Windows desktop-приложение с пакетной структурой src. Интерфейс загружается из Qt Designer UI-файлов, прикладные сценарии находятся в контроллерах, обратный отсчёт отделён от окна, а настройки проходят через Model, DTO, mapper и файловое хранилище.

~~~mermaid
flowchart LR
    UI[Qt UI: Timer_3 и TunesWindow]
    CFG[UI configurators]
    CTRL[Controllers]
    CLOCK[Clock]
    PRECISE[PreciseTimer]
    INFORM[InformTime]
    CTX[Context]
    MODEL[Model]
~~~

## Точки входа

### run_timer.py

Добавляет каталог src в sys.path и вызывает timer_3.main.main. Используется как простая точка запуска из репозитория и как источник для PyInstaller.

### timer_3.main

Создаёт QApplication, подключает освобождение pygame mixer при выходе и запускает главное окно Timer_3.

Класс Timer_3 не содержит бизнес-логики. Он:

- загружает _internal/timer_3.ui;
- создаёт Timer3Controller;
- создаёт Timer3UiConfigurator;
- показывает окно и передаёт управление event loop Qt.

## Главное окно

### Timer3UiConfigurator

Отвечает за статическую настройку и начальное состояние интерфейса:

- создаёт валидаторы времени;
- подключает Qt-сигналы к методам контроллера;
- восстанавливает или сбрасывает сохранённые поля;
- устанавливает активную вкладку;
- настраивает клавиатурный фокус и стиль активной кнопки.

Конфигуратор выполняется при создании окна и не управляет ходом таймера.

### Timer3Controller

Содержит пользовательские сценарии:

- обработку кнопок и редактирования полей;
- выбор активного формата времени;
- подготовку обычного таймера;
- подготовку и переключение интервалов циклического таймера;
- обновление полей остатка времени;
- запуск голосовых и финальных звуковых сообщений;
- открытие окна настроек.

Контроллер работает с интерфейсом через объект window, с настройками через Context и с отсчётом через Clock.

### FocusTransition

Хранит именованные схемы перехода по Tab для четырёх состояний:

- пустой обычный таймер;
- обычный таймер в формате часы + минуты;
- обычный таймер в формате минуты + секунды;
- циклический таймер.

Перед установкой новой схемы доступные виджеты переводятся в ClickFocus, после чего только нужные элементы получают StrongFocus или TabFocus.

## Обратный отсчёт

### Clock

Clock хранит seconds_left и два именованных callback:

- a_second_passed;
- end_of_timer.

На каждом тике остаток уменьшается, затем вызывается callback обновления. Если значение стало нулевым или отрицательным, следом вызывается callback завершения. Такой порядок гарантирует, что интерфейс сначала покажет ноль, а уже затем начнётся финальная обработка.

### PreciseTimer

Обычный периодический QTimer накапливает задержку обработчиков. PreciseTimer использует одноразовый QTimer и QElapsedTimer:

1. вычисляет ожидаемое время очередного тика;
2. измеряет фактическое прошедшее время;
3. определяет дрейф;
4. корректирует задержку следующего запуска.

Задержка не может стать отрицательной: минимальное значение равно нулю.

## Обычный таймер

~~~mermaid
sequenceDiagram
    actor User
    participant Controller as Timer3Controller
    participant Clock
    participant UI
    participant Inform as InformTime

    User->>Controller: Пуск
    Controller->>Clock: seconds_left и callbacks
    Clock->>Clock: start
    loop каждую секунду
        Clock->>Controller: a_second_passed(seconds_left)
        Controller->>UI: обновить время
        Controller->>Inform: голос или beep при условии
    end
    Clock->>Inform: end_of_ordynary_timer
    Inform->>Inform: проиграть MP3
    Inform->>Controller: завершить приложение
~~~

Название end_of_ordynary_timer сохранено в коде как существующий публичный метод, несмотря на опечатку в английском слове ordinary.

## Циклический таймер

Timer3Controller преобразует список интервалов в итератор. Для каждого интервала Clock перезапускается с новой длительностью.

После исчерпания итератора:

- при конечном режиме уменьшается число оставшихся повторов;
- если повторов больше нет, приложение завершается;
- иначе создаётся новый итератор и начинается следующий цикл;
- в бесконечном режиме итератор создаётся заново без изменения счётчика повторов.

Текущий индекс сбрасывается только при переходе к новому циклу.

## Звуковое и голосовое информирование

### InformTime

Голосовое сообщение запускается в daemon-потоке. Для каждого сообщения создаётся отдельный pyttsx3 engine. Неблокирующий Lock предотвращает одновременное воспроизведение нескольких сообщений.

Финальная мелодия воспроизводится через pygame. Локальный QEventLoop ожидает сигнал melody_finished, который формируется периодической проверкой состояния mixer.

Ошибки инициализации голоса печатаются и не останавливают отсчёт. Ошибка финальной мелодии считается фатальной, потому что дальнейший сценарий завершения не может быть выполнен корректно.

## Настройки

### Context

Context — фасад для контроллеров. Он объединяет Model и Storage и предоставляет операции:

- получить активный путь;
- изменить значение модели;
- сохранить модель;
- переключить профиль.

По умолчанию set_value сразу сохраняет настройки. Для групповых изменений можно передать save=False и выполнить одну итоговую запись.

### Model

Model содержит типизированное рабочее состояние и валидирует изменения через функции преобразования. Значения времени, интервалов сообщений и флаги приводятся к нужным типам до присваивания.

### DTO и mapper

DTO содержит только JSON-совместимые типы. Mapper выполняет три преобразования:

~~~mermaid
flowchart LR
    JSON[dict из JSON] --> DTO
    DTO --> MODEL[Model]
    MODEL --> DTO2[DTO]
    DTO2 --> JSON2[dict для JSON]
~~~

Некорректные значения отдельного поля не делают непригодным весь профиль: mapper подставляет значение по умолчанию только для этого поля.

### Storage

Storage отвечает за:

- основной профиль profiles/user.json;
- служебный active_settings.json;
- пользовательские профили в произвольных каталогах;
- нормализацию и проверку путей;
- безопасное чтение и запись JSON;
- накопление предупреждений для UI.

Storage не показывает диалоги. Он возвращает DTO и сохраняет предупреждения, которые позже отображает TunesController.

## Окно настроек

TunesWindow загружает _internal/tunes.ui и создаёт:

- TunesController — пользовательские действия, переключение файлов и вывод предупреждений;
- TunesConfigurator — числовые валидаторы и связи Qt-сигналов.

QSignalBlocker используется при обновлении флажка восстановления, чтобы программная перерисовка не запускала повторное сохранение.

## Ресурсы

Функция resource_path поддерживает два режима:

- запуск из исходников — путь считается относительно корня проекта;
- PyInstaller — путь считается относительно sys._MEIPASS.

Абсолютный пользовательский путь возвращается без изменения.

## Обработка ошибок

Ошибки делятся на две группы:

- восстановимые — повреждённый JSON, отсутствующий профиль, невозможность сохранить настройки; приложение использует безопасные значения и показывает предупреждение;
- фатальные — нарушенный внутренний контракт callback, неизвестный ключ модели, отсутствие финальной мелодии; показывается сообщение и приложение завершается.

## Направления расширения

### Добавление новой настройки

1. Добавить поле в Model и DTO.
2. Добавить ParamKeys и обработку Model.set_value, если поле изменяется из UI.
3. Обновить default_model.
4. Обновить оба направления mapper.
5. Добавить диапазон в settings_schema при необходимости.
6. Обновить TunesController и UI.
7. Добавить тесты mapper, model, storage и controller.
8. Обновить SETTINGS.md и пример JSON.

### Добавление нового режима таймера

1. Добавить UI-вкладку.
2. Создать отдельные методы подготовки и callback в Timer3Controller.
3. Подключить их через Timer3UiConfigurator.
4. Добавить схему в FocusTransition.
5. Проверить переходы Clock и завершение режима unit-тестами.
